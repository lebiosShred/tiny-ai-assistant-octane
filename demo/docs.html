Introduction & Product Architecture

The Tiny AI Assistant is an enterprise-grade sales pipeline coprocessor designed specifically for Octane Software Solutions to optimize prospect intake, pre-screening discovery preparations, and call synthesis deliverables. It aligns with standard playbook rules to support designated Sales Development Representatives (SDRs) — specifically Albert and Isha — in executing discovery operations while enforcing strict pricing sovereignty guidelines.

Business Objectives & Team Roles

The coprocessor implements a disciplined, simple sales process to generate and qualify high-value leads for Octane Software Solutions, resolving the lack of structure in early pipeline stages that historically caused deals to stall. The system design and workflow coordination are distributed across key stakeholder roles:

  • Amiel / Amendra Pratap (Director & Lead Engineer): Technical architect responsible for compiling the core codebase, Express backend integration, and Google Cloud Run deployment.
  • Amie Lebios (SEO & Marketing Team): Sole operator of digital assets, downloads page codebase, tracking, and HubSpot integration pipelines.
  • Sheila Ocana (Operations): Author of the Standard Operating Procedures (SOPs), training resources, and user workflows.
  • Anthony Coundouris (Sales Trainer & Coach): Reviewer of the sales components, developer of prompt guidelines, and lead coach for sales staff enablement.

The architecture is designed to leverage existing enterprise applications without requiring extra license spend, focusing on manual copy-paste workflows to establish process maturity before automation:

Pipeline Sequence Model

The application coordinates a 6-component process mapped to SDR daily operations:

Architecture Workflow 1. Prospect Schedules call on Booking Page (Component 01) →
2. SDR ingests Booking details into Prep Panel (Component 02) →
3. System compiles 12-point Dossier and Rapport Guides (Component 03) →
4. SDR runs call with Battlecard Questionnaire (Component 03/04) →
5. Call Directory & History logs the session metadata and restores workflows (Component 04) →
6. Synthesis Console parses transcript and outputs 9 deliverables (Component 05) →
7. SDR downloads ICS positional meeting invite for Founder Hand-over (Component 06).

Component 01: Client Booking Page

The booking site book.html provides an interactive calendar interface for prospects while dynamically applying calendar availability and buffer constraints based on the chosen host. A single scheduling link is used for all prospects across Australia (AU), New Zealand (NZ), and the Middle East (ME).

Designated SDR Hosts & Shift Coverage

Calls are routed dynamically to Octane's designated Sales Development Representatives (SDRs) based on timezone-deterministic shift windows:

  • Albert (SDR): Operates the early shift from 7:00 AM -- 2:00 PM AEST (Sydney time).
  • Isha (SDR): Operates the late shift from 2:00 PM -- 9:00 PM AEST (Sydney time).
  • Together, Albert and Isha cover a combined 14-hour window providing exactly 28 x 30-minute booking slots per day.

Host Selection Removed The booking page no longer presents a host selector dropdown. Since all pre-screen calls are exclusively handled by the Round Robin SDR pool (Albert and Isha), the host assignment is automatic. Calendar Widget Integration & Context Page

The booking widget is embedded within a contextual page that gives the attendee information about what to expect — not presented as a standalone, bare calendar widget. The structure of this page is inspired by the professional context page model at salesstar.com/steve-hughson-meeting.

Offline QR Code Access

A QR code is generated dynamically on the booking page linking directly to its URL. This code is required for offline materials such as business cards, brochures, or event flyers, allowing prospective clients to scan and book sessions instantly. SDRs can download the high-resolution QR code directly in PNG format from the interface.

Information Collected at Booking

To pre-qualify prospects, the booking widget collects the following structured parameters:

  1. Prospect Name, Company Name, & Job Title (e.g. CFO, Head of FP&A).
  2. Company Email Address.
  3. Company Website URL (grounding context).
  4. Service Track Interest: Planning & Analytics (TM1) or Generative AI.
  5. Free-text Discussion Request ("What would you like to discuss").
Simplified Booking Flow Since the host selector has been removed, the calendar always displays current-month dates with a 12-hour buffer. The booking page automatically assigns the SDR based on the selected time slot (Albert for morning, Isha for afternoon/evening).

Component 02: Ingestion & Call Prep

Before a requirements session call, the assigned SDR prepares using the AI Assistant. This module accesses GDrive client folders, SOWs, and history files to give the representative context about the account.

Manual SDR Inputs (6 Core Inputs)

The SDR gathers and pastes the following 6 core inputs into Step 1 of the dashboard to prepare the briefing dossier:

  1. Client Name, Company Name, & Job Title (e.g. CFO, Head of FP&A).
  2. Completed Booking Form Intake Summary (copied from the book.html success card clipboard output).
  3. LinkedIn Profile Text (copied from LinkedIn PDF export).
  4. Company Website URL.
  5. Service Track Interest (AI or TM1).
  6. Company Email Address.

Note: The CRM check (verifying if contact/company exists in HubSpot and pulling history) is currently a manual step listed in the brief and is deferred from direct system integration.

Google Drive File Attachment Explorer

The assistant links to Google Drive directories to compile deep contextual briefings. The connection accesses files shared with the service account: 28323029503-compute@developer.gserviceaccount.com.

  • Directory Browsing: Live dynamic loading of folder indices via the /api/gdrive/list endpoint.
  • Full-text Search: Leverages debounced text search (300ms) calling /api/gdrive/search to locate files matching keywords in name or contents.
  • Content Extraction:
    • Google Docs: Exported as text/plain.
    • Google Sheets: Exported as text/csv.
    • PDFs: Array buffer text parsed via pdf-parse.

12-Section Briefing Dossier

Generating the prep brief runs the inputs against the Mistral model to construct a 12-section dossier. Dossier progress is tracked via a completeness progress meter (0--100%). The dossier outputs the following 12 components:

  1. Section 1: LinkedIn Analysis (Detailed profile breakdown & recent social activities).
  2. Section 2: Company Products & Services (Core business offerings and revenue lines).
  3. Section 3: Octane Services Alignment (Specific product matches from the services catalog).
  4. Section 4: Octane Competitors (Firms competing with Octane for the deal).
  5. Section 5: Competing Applications (Software products competing with TM1/watsonx, e.g. Anaplan, Workday).
  6. Section 6: Complementary Applications (Software that integrates, e.g. SAP, NetSuite, Power BI).
  7. Section 7: TM1 and AI Applications (Relevance mapping for multidimensional calculations or AI agents).
  8. Section 8: Relevance Assessment (Custom thesis showing why the track matters to this specific prospect).
  9. Section 9: Likely Pain Points (Consolidation lag, memory constraints, version control risks).
  10. Section 10: Conversation Starters (3 targeted icebreaker questions to demonstrate relevance immediately).
  11. Section 11: Customer Profile Classification (Playbook segment mapping, e.g. On-Premise TM1 Shop).
  12. Section 12: Travel Distance Estimate (Calculated driving time and distance from Amendra's Richmond, Melbourne home/office location to the prospect's appointed meeting location).

Component 03: Live Discovery Call

Step 2 contains call facilitation tools, including teleprompters, discovery scripts, and pre-compiled icebreaker dossiers. The requirements session lasts exactly 30 minutes and is conducted by Albert or Isha.

Meeting Objectives & SDR Rules

SDRs must adhere to the 5 primary objectives during the pre-screen call:

  1. Build Rapport: Open the call using the 3 conversation starters compiled in the Rapport Guide (Component 02).
  2. Execute Discovery Questionnaire: Walk the prospect through the 12 structured questions from the battlecard script.
  3. No Typing Allowed: The SDR must focus fully on conversation. Answers are captured via automatic transcription (Fathom, Jamie AI, or Fireflies).
  4. Post-Call Synthesis: SDR copies the transcript from the recording tool and pastes it into Step 3 to map answers and auto-generate reports.
  5. Schedule Hand-over: Before ending the call, the SDR must book a Positional Meeting with Amendra Pratap.

Pre-Screen Call Rapport Guides

Asynchronously generated upon Dossier compilation, the Rapport Guide accordion auto-expands on step transition. It summarizes findings into actionable call prompts:

  • Opening Statements: Curated hooks to build immediate rapport.
  • Key Facts: Vital prospect metrics (budget parameters, consolidated sheet counts).
  • Core Pain Points: Primary business obstacles identified during booking.
  • Forbidden Phrases: Guardrail warnings blocking SDRs from mentioning unapproved discounts or service items.

Battlecard Questionnaire Variants

Selectable discovery scripts available on the teleprompter panel:

Variant A: First-Time TM1 / Planning Analytics Users

Targeting: Prospects consolidating data manually in Excel who do not run a dedicated multi-dimensional database.

  1. ERP Integration: What general ledger/ERP system (e.g., SAP, MS Business Central, NetSuite) are you using, and does it currently integrate with your planning tool?
  2. Spreadsheets Count: How many separate Excel spreadsheets are you manually consolidating for your budgeting and forecasting, and are there issues with version control?
  3. Planning Workflows: What specific planning workflows (e.g., actuals, payroll allocations, cost analysis, budgeting, forecasting) are you executing, and are allocations inconsistent or time-consuming?
  4. Reporting Stack: What reporting tools (e.g., Power BI, Qlik, Tableau, Excel PAX/PAW) do you use for management reporting, and do you manually export CSV files to reconcile data?
  5. Drill Down Capability: Do users need to drill down from high-level reports to transaction-level GL data, and do you perform multi-currency transactions?
  6. Admin Staffing: Do you have internal developers/admins to manage these systems, or is there a key-person risk if someone leaves?
  7. User Counts: How many planning contributors, read-only users, and administrators are involved, and would they need formal training?
  8. Repetitive Operations: What repetitive financial tasks feel most manual, and would conversational AI access to financial queries benefit your executives?
  9. Timeline: What is your target timeline for going live, and do you need a parallel run?
  10. Budget Framework: Is there a budget allocated for licensing and delivery, and what is your internal approval/purchase order process?
  11. Tool Evaluation: Have you evaluated other tools (e.g. Workday, Anaplan), and who else is involved in the final decision?
  12. Success Criteria: What does success look like, and would a 60-day trial of connectors (like DataFusion) or a free Proof of Concept (POC) help validate?

Variant B: Existing TM1 / Planning Analytics Users

Targeting: Prospects who already run IBM Planning Analytics / TM1 but face support bottlenecks, performance limits, or require upgrades.

  1. Version & Deployment: What version of TM1/Planning Analytics are you running, and is it deployed on-premise or in the IBM Cloud?
  2. Instance Count: How many TM1 instances do you run (e.g., production-only, or separate dev and test environments)?
  3. Model Scale: How many models, cubes, dimensions, and user groups are you currently running?
  4. Performance Metrics: Have you checked your system's performance, RAM usage, hard disk space, or feeder memory usage?
  5. Log File Size: Are log files being automatically cleared, and what is the typical size of your TM1 log files (e.g., is it under or over the 50MB standard)?
  6. Report Load Times: What are the typical report load times for your end-users, and are they above the 5-second threshold?
  7. Team Staffing: Do you have dedicated in-house TM1 administrators/developers, or are you dependent on key individuals?
  8. Vendor Lock-in: Are you currently working with another TM1 vendor? Are you locked into a rigid contract with separate rates for support and development?
  9. Backlog Scale: What is your current backlog of enhancements, bugs, or data reconciliation tasks, and how is it prioritized?
  10. Training Portals: Have your TM1 developers and power users had formal training, and would they benefit from free access to professional training courses?
  11. Reporting Integration: Are you using Power BI, Tableau, or Qlik, and do you have a direct database connection?
  12. Approval Timeline: Who has final authority to approve support changes, and what is the timeline to transition support?

Variant C: First-Time Generative AI Users

Targeting: Enterprise prospects wanting to automate processes or integrate AI agent networks.

  1. Reporting Bottlenecks: How many slides are in your monthly executive financial reports, and how much time does the finance team spend manually extracting, cleansing, and formatting data for them?
  2. Data Source Matrix: What enterprise systems and data sources (e.g., TM1, Adobe Analytics, Google Ad Manager, Adobe AdSlot, BigQuery, SQL) need to connect for automated reporting?
  3. Natural Language Queries: Would executives and managers benefit from asking natural language questions (e.g. "AskFinance") to query financial data in real time?
  4. Operational Repetition: What other areas in the business (e.g. Sales, Editorial, HR, IT, Procurement, Legal) have repetitive workflows ripe for automation?
  5. AI Exposure: Have you experimented with or deployed any generative AI or automation tools internally?
  6. Cloud Stack: What is your primary cloud environment (e.g. GCP, AWS, Azure, on-premise) and how do you manage data security?
  7. Access Control: Do you require specific role-based access controls and security protocols for financial data queried by AI?
  8. Co-Creation POC: Would you be open to a 2-to-6 week co-creation Proof of Concept (POC) to demonstrate value before full production rollout?
  9. Resource Commitment: Can you commit a primary business contact and technical resource to collaborate during a 2-to-6 week POC?
  10. Decision Timelines: Are you willing to commit to a Decision Workshop within 10 days of POC completion to confirm next steps?
  11. Budget Awareness: Are you aware of the indicative costs for enterprise generative AI licensing ($160k+/yr) and implementation services ($125k+)?
  12. Stakeholders: What is your timeline for starting an AI pilot, and who are the key executive stakeholders involved?

Component 05: Automated Reports & Synthesis

Pasting a transcript in Step 3 compiles a suite of 9 reports (incorporating the 7 playbooks and standard summaries). The assistant ensures output layout compliance and structural integrity.

The 9 Generated Deliverables

The coprocessor synthesizes 9 distinct deliverables, mapping the 7 required reports from the brief plus 2 internal/archival documents:

  1. Questionnaire Answers: Formatted responses mapping the transcript answers to the 12 discovery script questions based on the selected variant.
  2. Qualification & Next Steps: The SDR lead scorecard containing the Qualification Score (HOT, WARM, or COLD), scoring rationale, recommended next steps, and red flags.
  3. Migration Report: A branded technical migration checklist and readiness assessment, crucial for legacy TM1 upgrade prospects.
  4. Client Recap Email: A standard follow-up email layout compiling the top 3 takeaways and automatically embedding the Vidyard/Teams screencast link.
  5. Summary Sheet: An internal table summarizing attendees, service track interest, key discussion points, and prospect sentiment.
  6. Meeting Notes: Chronological meeting minutes capturing the contextual details, technical notes, and direct quotes from the call.
  7. Consultative Proposal: A preliminary B2B scope document outlining requirements, proposed services (grounded in standard catalog pricing), approach/timeline, and team structure.
  8. Action Items: A tasks matrix outlining clear follow-up deliverables and explicit deadlines assigned to the SDR or the client.
  9. Raw Call Transcript: An archived record of the copy-pasted transcript.

Component 07: Settings Panel

The ⚙ Assistant Configurations & Custom System Instructions panel is a collapsible settings drawer accessed via the ⚙ Settings button in the dashboard header. It controls the AI engine, persona behavior, prompt templates, knowledge base documents, and developer options. All settings persist to localStorage and are restored on page reload.

Section 1: API Authentication

Configures the connection to the large language model (LLM) backend that powers the AI Coprocessor.

Control ID Purpose
LLM Provider #settings-api-provider Selects the AI provider (Mistral AI, Anthropic Claude). This determines the API authentication format and model catalog available in the engine dropdown.
API Base URL #settings-api-url The endpoint URL for the AI backend. Default is /api/chat (proxied through the Express server). Can be overridden to point to a custom self-hosted endpoint or direct API URL.
LLM Model / Engine #settings-api-model Selects the specific model to use. Options include Mistral Large, Mistral Small, Claude 3.5 Sonnet, and Claude 3.5 Haiku. The model determines response quality, latency, and token cost.
How it works When the SDR clicks "Save Configuration", these values are written to localStorage and sent as headers/body parameters on every subsequent AI request. The Express backend reads the provider and model to route the request to the correct upstream API.

Section 2: Persona Tone & Behavior Presets

Controls the writing style and analytical posture of all AI-generated outputs (dossiers, reports, emails, proposals). The selected preset modifies the system prompt wrapper injected before every LLM call.

Preset Name Behavior Description
Clinical / Professional B2B (Default) Formal enterprise tone. Direct, structured outputs. No filler language. Suitable for CFO-facing deliverables.
Empathetic / Warm B2B Softer tone with empathetic framing. Acknowledges pain points before presenting solutions. Suitable for first-contact rapport.
Skeptical / Critical Analyst Challenges assumptions in the transcript. Flags inconsistencies and red flags. Outputs include counter-arguments.
High-Detail Consultant Verbose, deeply technical outputs. Includes implementation specifics, architecture notes, and expanded rationale blocks.
Concisely Direct Minimal prose. Bullet-point outputs. Maximum signal density. Suitable for internal team handoffs.
Custom (Manual Prompts Modification) Unlocks direct editing of the system prompt textareas in Section 3. Use this when none of the presets match the desired output style.

Section 3: Custom System Instructions

Two editable prompt textareas that define the core behavior of the AI engine for the two primary workflows. These are pre-populated with production-grade system prompts and can be customized when the "Custom" tone preset is selected.

Prompt Field ID Controls
Prospect Call Prep Dossier Prompt #settings-prep-prompt The system instruction sent to the LLM when generating the 12-section pre-call dossier (Step 1). Defines how LinkedIn data, company website, booking intake, and GDrive SOWs are synthesized into actionable briefing sections.
Call Transcript Synthesizer Prompt #settings-synth-prompt The system instruction sent to the LLM when generating reports from call transcripts (Step 3). Controls how questionnaire answers are extracted, pricing sovereignty is enforced, and deliverable formatting rules are applied.
Caution Modifying these prompts without understanding their structure can break report formatting, remove pricing guardrails, or cause hallucinated outputs. Only modify when using the "Custom" tone preset and test with a sample transcript first.

Section 4: Knowledge Base Documents

Manages the playbook files and training documents that are injected into every AI request as grounding context. The assistant uses these files to ensure outputs align with Octane's actual service offerings, pricing, and sales methodology.

Feature Description
Upload Drop Zone Drag-and-drop or click-to-upload interface supporting PDF, DOCX, TXT, and MD files (max 2MB per file). Uploaded files are stored in the Express backend's uploads/ directory and registered in the knowledge file index.
Stored Playbooks & Files Lists all active knowledge base documents. Core system files (e.g., customer profiles playbook, services catalog) are marked with a lock icon and cannot be deleted. User-uploaded files show a red delete button.
🔄 Restore Defaults Resets the knowledge base to the original factory playbook files, removing all user-uploaded custom documents. Does not affect API credentials or prompt settings.

Section 5: Developer Options

Developer-facing toggles that control UI behavior for testing and demonstration purposes.
